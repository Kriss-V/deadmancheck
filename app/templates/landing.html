Three ways a cron job fails

A basic heartbeat check only catches the first. DeadManCheck catches all three.

💀

It stops running

The server was replaced, the crontab got wiped, the scheduler died. Your job checks in after each run — when it goes quiet, you get an alert.

⏱

It runs too long

Your 2-minute job suddenly takes 20. DeadManCheck learns each job's normal runtime from its own history and alerts on anomalies — no thresholds to set or maintain.

🔬 1 monitor free

It runs — but does nothing

Exit code 0, on time, and it exported 0 rows. Send a count with your ping, set a rule like count > 0, and get alerted when the job technically succeeded but did no work.

Output assertions · free on 1 monitor, unlimited on Pro

Your backup ran. It exported 0 rows. You found out three weeks later.

A plain heartbeat only asks did it run? Output assertions also ask did it actually do anything? Include a count in your ping — rows exported, files copied, records synced — and DeadManCheck checks it against your rules on every run. How output assertions work →
